# Первый шаг — бот-навигатор для MAX

«Первый шаг» помогает иностранному студенту пройти понятный маршрут после приезда в Россию: открыть персональный чек-лист, посмотреть карточку каждого шага, отметить выполненное и настроить напоминание перед дедлайном.

Проект реализует MVP из ТЗ: JavaScript, официальный MAX Bot API SDK, JSON-хранилище, Docker, long polling для локального запуска и webhook для production.

## Что умеет бот

- персонализированный онбординг: срочные шаги для только приехавшего студента, выбор уже оформленных документов для продолжающего обучение и отдельный режим просмотра;
- чек-лист из 8 шагов с прогресс-баром;
- карточки «что это», «где делать», «что взять», «срок», «что будет при просрочке»;
- отметка шага как выполненного;
- дата въезда и расчёт модельных дедлайнов;
- ручной ввод дедлайна для шагов без универсального срока;
- настраиваемые напоминания за 1, 2, 3 или 7 дней до дедлайна, изменение дедлайна и отключение;
- напоминания доступны только для активных пунктов и автоматически отменяются после выполнения;
- повторная попытка при ошибке отправки напоминания;
- сохранение состояния в JSON с атомарной записью;
- `/healthz` для Docker и мониторинга;
- защита webhook заголовком `X-Max-Bot-Api-Secret`.

Контент в `src/content.json` — демонстрационный. Бот прямо сообщает пользователю, что требования зависят от гражданства, региона, визы и вуза. Перед пилотом юридические тексты и региональные маршруты нужно проверить с профильными специалистами.

## Быстрый запуск локально

Требования: Node.js 24.5+ и токен бота MAX.

```bash
cp .env.example .env
npm install
npm test
npm start
```

В Windows PowerShell первая команда выглядит так:

```powershell
Copy-Item .env.example .env
```

Открой `.env` и вставь токен:

```dotenv
MAX_BOT_TOKEN=сюда_токен_из_MAX
BOT_MODE=polling
```

Long polling подходит для локальной разработки. При его запуске SDK удаляет существующие webhook-подписки, потому что MAX не разрешает использовать оба режима одновременно.

## Запуск через Docker

```bash
cp .env.example .env
docker compose up --build -d
docker compose logs -f bot
```

Состояние хранится в volume `bot-data` и не теряется при пересоздании контейнера.

Проверка процесса:

```bash
curl http://localhost:3000/healthz
```

## Production webhook

Webhook должен быть доступен снаружи по HTTPS. Обычно TLS завершается на reverse proxy, а контейнер слушает порт 3000.

```dotenv
MAX_BOT_TOKEN=сюда_токен_из_MAX
BOT_MODE=webhook
PUBLIC_BASE_URL=https://bot.example.com
WEBHOOK_SECRET=длинная_случайная_строка
PORT=3000
```

Если `WEBHOOK_PATH` пуст, приложение использует безопасный стабильный путь `/webhook/<sha256-токена>`. При старте бот сам регистрирует webhook и оставляет активной только эту подписку.

## Команды пользователя

- `/start` — показать онбординг;
- `/checklist` — открыть чек-лист;
- `/arrival 2026-09-29` — задать дату въезда;
- `/reminders` — открыть список и настройки напоминаний;
- `/reset` — удалить прогресс и напоминания;
- `/help` — показать помощь.

## Как масштабировать

Для пилота достаточно одного процесса и JSON-файла. Для нескольких экземпляров нужно заменить `JsonStore` на Redis или базу данных и вынести очередь напоминаний в отдельный worker. Региональные адреса и правила лучше хранить отдельными наборами контента, сохраняя идентификаторы шагов и сценарий интерфейса.

## TLS-сертификат MAX

API MAX использует цепочку российского удостоверяющего центра. Проект добавляет корневой сертификат Минцифры только в TLS-контекст процесса Node.js — системное хранилище Windows не изменяется. Перед использованием сертификата код проверяет закреплённый SHA-256-отпечаток `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`.
