# Техническая информация для проверки

## Ссылки

- Чат-бот в MAX: [@t327_hakaton_max_bot](https://max.ru/t327_hakaton_max_bot)
- Git-репозиторий: [github.com/Chiryusha/MAX_BOT](https://github.com/Chiryusha/MAX_BOT)
- Ветка для проверки: `main`
- Контрольная версия: актуальный `HEAD` ветки `main`; точный SHA передаётся вместе со ссылкой на репозиторий.

Для работы с ботом отдельная учётная запись не нужна. Проверяющий открывает ссылку в MAX, нажимает «Начать» или отправляет `/start`. Логины и пароли в проекте не используются.

## Короткий сценарий проверки

1. Отправить `/start`.
2. Выбрать «Я студент, только приехал» и открыть срочные пункты чек-листа.
3. Открыть карточку документа, поставить напоминание и изменить его интервал через `/reminders`.
4. Отметить пункт выполненным: напоминание должно исчезнуть. Вернуть пункт в работу: настройка напоминания снова доступна.
5. Снова отправить `/start`, выбрать «Я уже учусь» и отметить документы, которые уже оформлены.
6. Выполнить `/arrival` и попробовать указать завтрашнюю дату: бот должен отклонить её.
7. Выполнить `/reset`, чтобы удалить тестовый прогресс.

## Запуск и проверка кода

Требования: Node.js 24.5+ и токен бота MAX.

```powershell
Copy-Item .env.example .env
npm ci
npm test
npm run lint
npm start
```

Проверка Docker-конфигурации и запуск контейнера:

```powershell
docker compose config
docker compose up --build -d
curl http://localhost:3000/healthz
```

Рабочие переменные окружения перечислены в `.env.example` и подробно описаны в README. Обязательное секретное значение только одно — `MAX_BOT_TOKEN`; оно передаётся отдельно и не хранится в Git.

## API и тестовые данные

Собственного прикладного API у решения нет. Бот работает через официальный MAX Bot API с помощью пакета `@maxhub/max-bot-api`. Поэтому отдельные пункты о публичном адресе собственного API, тестовых ролях, логинах, паролях и `DATA-API.yaml` к проекту не применяются.

Приложение открывает два служебных HTTP-маршрута:

- `GET /healthz` — проверка готовности процесса;
- `POST /webhook/{tokenHash}` — получение обновлений MAX в webhook-режиме.

Их схема находится в `docs/openapi.yaml`. При запуске через long polling внешний HTTPS-адрес не требуется.

Контент чек-листа хранится в `src/content.json`. Пользовательские отметки и напоминания создаются во время проверки и сохраняются в `data/state.json`; заранее подготовленные тестовые аккаунты или персональные данные не нужны.

## Состав решения

- 8 карточек документов и процедур;
- персонализация для нового и продолжающего обучение студента;
- сохранение прогресса;
- контроль даты въезда;
- редактируемые напоминания;
- long polling и webhook;
- JSON-хранилище с атомарной записью;
- Docker health-check;
- автоматические тесты доменной логики, сценариев, хранилища и TLS.

Юридически значимые сроки необходимо сверять с международным отделом вуза и официальными ведомствами. Это предупреждение показывается пользователю внутри бота.
